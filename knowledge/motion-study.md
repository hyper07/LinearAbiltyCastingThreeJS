# Character motion: dances, emotes, idles and locomotion for any character

Studied 2026-11-26. The user asked for varied, high-quality movement for every
character in our games (dances, celebrations, emotes, idles, locomotion, sports
moves), learned from open-source motion and applied cheaply and legally. The
proof runs in `motion-lab.html` (dev only): one CC0 dance clip on a
human, on a big-head humanoid and on a Kickrani plush rider, next to a
procedural, beat-synced dance and an upper-body emote over riding.

```bash
npm run kb -- dance chest pop beat          # techniques → sections of this file
npm run kb -- retarget plush chibi
npm run kb -- --show own.shared.motion      # the module
npm run kb -- dance --models                # animated models in the library
```

Code: `src/shared/motion/dance.js` (pure: beat clock, curves, move library,
routines, combos, springs, pose → plush rig), `clipTools.js` (pure: keyframe
reduction, masks, root motion), `retarget.js` (three.js: aim retargeting onto
one-bone limbs, baking poses into clips, compressing, masking). Tests:
`tests/unit/motion.test.mjs`.

## 1. The short answer

- **Humans and humanoids** (Gloamreach heroes, Kickrani folk, VRM avatars): play
  the CC0 clips we already fetch — Mesh2Motion's 234 human clips (five dances,
  a moonwalk, a dab, clapping, victory, greetings, nods, idles, many walks and
  runs) and Quaternius' Universal Animation Library — retargeted with
  `retargetClip()` from `src/library/characters.js`.
- **Plush and chibi characters** (Kickrani riders, Snowpuff, Arcademia creatures):
  their limbs are one bone each and their heads hide anything above the
  shoulder. Two ways, both in `src/shared/motion/`:
  - **procedural** (`dance.js`): a pose library on a beat clock, original combos
    from generic moves, springs for ears and tails — tiny, deterministic (easy to
    sync online), always on the music;
  - **retargeted** (`retarget.js` `aimRetarget`): any humanoid clip, each limb aimed
    along the source's shoulder→hand / hip→foot chain, clamped to what a plush can
    show, baked and compressed.
- **Never ship** clips whose licence doesn't allow it: AIST++, Bandai Namco,
  Motorica, LaFAN1, SFU, Ready Player Me's library and anything generated by a
  model trained on AMASS/HumanML3D or AIST++ (§9). Mixamo and Rokoko are fine
  inside a built game, never as raw files in this public repo.

## 4. Pipelines in three.js (r185)

### 4.1 Loading

- **GLTFLoader** with `setMeshoptDecoder(MeshoptDecoder)` (`characterLoader()`):
  Mesh2Motion files are meshopt-compressed. Clips arrive in `gltf.animations`.
  Track names drop characters a node name can't hold (`mixamorig:Hips` →
  `mixamorigHips`, `upperarm.l` → `upperarml`): look bones up both ways
  (`THREE.PropertyBinding.sanitizeNodeName`).
- **FBXLoader**: Mixamo, Rokoko, KayKit FBX. FBX from Mixamo is in **centimetres**
  (scale 0.01) and may carry a `Take 001` plus a T-pose frame 0. Prefer
  converting to GLB offline (Blender, or `FBX2glTF`) so the game loads one format.
- **BVHLoader** (`three/addons/loaders/BVHLoader.js`) → `{ skeleton, clip }`.
  Gotchas, all met in the lab:
  1. The rest skeleton has its **root at the origin**; the frames carry the
     absolute hip position (85 cm up in `pirouette.bvh`). Set the root's rest
     position to the first frame's before retargeting, or the hip height is read
     as motion and the body floats.
  2. Units are whatever the capture used (cm for CMU): scale the view, not the clip.
  3. A bone-only skeleton has no mesh, so `retargetClip()` (which measures leg
     length from mesh bounds) needs foot markers: a tiny invisible mesh under each foot.
  4. Channel order per joint is in the file (`Zrotation Xrotation Yrotation`); the
     loader handles it.
- **VRM / VRMA**: a `.vrm` loads as glTF (no three-vrm needed for skinning;
  `vrmExpressions()` reads the face blend shapes). VRM 0.x faces −z: bake and show
  it inside a parent turned by π. `.vrma` needs `@pixiv/three-vrm-animation`;
  skip it until there is a VRMA source we may ship.

### 4.2 Retargeting

| Tool | When | Notes |
|---|---|---|
| `retargetClip(target, source, clip, map)` in `src/library/characters.js` | humanoid → humanoid with the same joints (Mesh2Motion/UAL → Mixamo, VRM, KayKit) | each target bone first aligned to point where the source bone points at rest (cancels A- vs T-pose), then follows the source's world-space change from rest; hips scaled by leg length. Maps: `BONE_MAPS.mixamo`, `.kaykit`; the lab adds CMU-Daz → Mixamo and → Mesh2Motion |
| `aimRetarget(target, source, clip, map, o)` in `src/shared/motion/retarget.js` | humanoid → plush/chibi with one-bone limbs | limbs aim along source chains; spine/head copy turns; facing frames; side pairing; clamps (§5). Maps: `PLUSH_FROM_UNREAL`, `PLUSH_FROM_MIXAMO`, `PLUSH_FROM_CMU_DAZ` |
| `SkeletonUtils.retargetClip(target, source, clip, options)` (three addon) | quick tests | gotchas: `options.names` maps **target → source** names; the hip is `options.hip` (default `'hip'`); it compares *bind matrices*, so A-pose vs T-pose bodies twist unless you pass `localOffsets`; `preserveBoneMatrix`/`useFirstFramePosition` interplay; `fps` defaults to the densest track; hips position is copied in source units unless `scale` is set. Ours handles rest-pose differences and leg-length scaling for us; use ours |
| `own.people.retarget` (`src/city/people.js`) | Kickrani's walkers | turn-from-rest copied bone by bone in each skeleton's own frame |

Both of ours **bake**: they sample the source with a mixer at 30 fps and write
new quaternion tracks for the target, so playback costs nothing extra. Bake once
per (body, clip) and cache the clip (they are body-specific).

### 4.3 Mixer layers, additive clips, masks and crossfades

- **Crossfade**: `next.reset().play(); current.crossFadeTo(next, 0.25, false)`
  (0.15–0.3 s for emotes, 0.3–0.5 s locomotion → idle). Interrupt from the
  *current blended pose*, not from the start of the old clip
  (`vendor/3dviz/knowledge/motion-profile/interruptible-animation-transition.json`).
- **Masks** (upper body only while riding a scooter): three has no mask object.
  Make a clip with only the wanted tracks — `maskClip(clip, MASKS.upperBody)` or a
  name list — and play it as a second action on the same mixer at weight 1. Actions
  that own different bones don't fight; where they overlap, weights blend. For
  procedural poses, `applyPlushPose(rig, pose, { mask: UPPER_BODY, weight })` after
  the base pose (the lab's bear: riding + a wave on `armR` and `head`).
  Masks for our rigs: `MASKS.upperBody / lowerBody / arms / head` in `clipTools.js`.
- **Additive**: `THREE.AnimationUtils.makeClipAdditive(clip, refFrame)` then
  `action.blendMode = THREE.AdditiveAnimationBlendMode`. Use for small layers over
  anything: breathing, a head shake, a flinch, "proud chest" over a walk. Additive
  actions are applied after the normal ones (three.js example
  `webgl_animation_skinning_additive_blending`). Keep additive weights ≤ 1.
- Layer order that works: base locomotion (normal) → upper-body emote (masked,
  normal, weight eased 0→1 over 0.2 s) → additive accents → procedural secondary
  motion and IK last, after `mixer.update()`.

### 4.4 Root motion

- In-place clips (Mesh2Motion default, `UAL1_Standard`) keep the vertical bob
  and turn; the game moves the character. Root-motion clips (`-rm`, `UAL1_Standard_RM`)
  carry the travel in the hips/root track.
- For a game character, play in place and move by the game's speed; match the
  clip's playback rate to it: `action.timeScale = speed / clipSpeed`, where
  `clipSpeed = splitRootMotion(rootTrack.values).delta / duration` from the
  `-rm` twin. That is what kills foot sliding.
- For dances: in place, always (`aimRetarget` default `root: 'inPlace'`); a dance
  that travels is staged by the game (spot marks), not by the clip.

### 4.5 Compressing clips

| Step | Tool | Effect (measured in the lab, plush clips at 30 fps) |
|---|---|---|
| Keyframe reduction | `compressClip(clip, { angleTol: 0.006, posTol: 0.0015 })` (Ramer–Douglas–Peucker per track, angle error for quaternions) | body roll 1,544 → 556 keys (−64 %), Charleston 552 → 353, arm pump 480 → 252, victory 448 → 225, CMU pirouette 1,192 → 969 (mocap noise keeps more) |
| Drop constant tracks | `dropConstant: true` | fingers and toes that never move |
| Offline resample | `npx @gltf-transform/cli resample in.glb out.glb` | the same idea on GLB files |
| Quantise + compress | `gltfpack -cc` or `gltf-transform meshopt` (EXT_meshopt_compression with its quaternion filter, KHR_mesh_quantization) | Mesh2Motion's files are already this small; ~4–8× smaller animation data |
| Draco | — | **geometry only**: it does not compress animation |

Rule of thumb: an emote clip for a plush should end up under 10 KB.

### 4.6 Baking procedural motion into clips

`bakePoseClip(rig, t => routine.sample(clock(t)), { duration, fps: 30 })` records
the pose function as tracks (joints, hips position, arm reach as scale, the
squash/tilt/turn groups), so a procedural dance can be crossfaded with clip
actions, exported with `GLTFExporter` (`{ animations: [clip] }`) and played by any
mixer. Bake when the motion must mix with clips or ship as a file; stay live
(cheaper, always on the music) otherwise.

## 5. Retargeting onto chibi and plush bodies: the rules

The plush riders (`src/city/plushRider.js`, `src/snowpuff/render/riderModel.js`)
share one rig: `root → hips → chest → head (earL, earR) / armL, armR`, `hips →
legL, legR, tail(, tail2)`, every limb **one bone**; the head is ~0.68 wide on a
0.42-wide body; shoulders sit at the head's lower edge (y 0.38 vs head centre 0.67,
radii 0.34 × 0.29 × 0.30); an arm is 0.18 long. Conventions: the sculpt faces +z;
arms `rotation.y` swings forward, `rotation.z` raises (armL at −x raises with −z);
legs `−x` kick forward; chest/head `+x` bend forward.

1. **One-bone limbs aim along the source chain.** Shoulder → wrist, hip → ankle:
   where the hand goes, the paw goes. A one-bone arm copying the upper arm alone
   points wrongly whenever the elbow bends.
2. **The visibility envelope.** A paw raised more than ~50° above horizontal
   (`armRaise` > 1.7 from the rest droop) is inside the head. So "arms up" is a
   **V out to the sides** (`clampAim` `maxUp 0.75`), never straight up; a raised paw
   doesn't swing across the face (`armSwingHigh 0.45`); claps meet in front of the
   tummy (raise 0.9), below the chin. `PLUSH_LIMITS` holds the numbers.
3. **Rubber-hose reach.** When a paw must read (a wave, a point, a cheer), scale
   the arm bone up 20–25 % (`reachL/reachR` channels). Cartoon arms stretch; nobody
   notices the paw growing, everybody notices the wave.
4. **Pair sides by position, not name.** The plush `armL` sits at −x on a sculpt
   that faces +z, i.e. on the character's **right**. `aimRetarget` compares each
   limb's side in the facing frames and swaps chains when the names lie.
5. **Facing frames, not raw world axes.** Build (left, up, forward) for each body
   (`facingFrame`); the source's from its named shoulders (`facingFromSides`), the
   target's given (`body.getWorldDirection()`). This cancels Z-up armatures, VRM's
   −z and T- vs A-pose.
6. **Hips: scale by leg length, clamp the drop.** Vertical hip motion × (target hip
   height ÷ source hip height), then clamped to −25 %…+60 % of the target's hip
   height: stubby legs can't squat deep, so a deep human squat becomes a squash
   (`stretch` −0.1) instead.
7. **In place.** Drop the horizontal travel; keep the bob.
8. **Exaggerate, then hold.** Small bodies read motion by silhouette: bigger angles
   on chest and head (chest pop −0.34 rad vs ~−0.15 on a human), whole-body
   squash/stretch (±0.06–0.14, volume kept: `squashScale`), and 60–100 ms holds on hits.
9. **Ears and tails follow, they don't lead**: springs driven by the body's vertical
   speed and sway (§7), never keyed.
10. **Turns with the body.** If the source dancer turns (the body roll turns ~45°),
    the plush turns too; for a front-facing performance, use the procedural moves or
    clamp the hips' yaw.

Measured on the lab's machine: aim-retargeting a 6.4 s clip onto a plush takes
~9 ms; `retargetClip` onto Teddy (67 bones) ~150 ms including loading.

## 6. Procedural dance: recipes and exact timing

### 6.1 The beat clock

```
spb   = 60 / bpm                       seconds per beat
beat  = (t − offset) / spb             offset = time of a downbeat (beat 1)
phase = beat − floor(beat)             0..1 inside the beat
beatInBar = floor(beat) mod 4;  count = floor(beat) mod 8   (dancers count "1…8")
```

`beatClock(bpm, { offset })` returns that. **Use the measured tempo**: the podium
track was asked for 140 BPM; librosa measures 143.6 (`measured.tempo` in
`public/audio/bgm/manifest.json`). At 140 a dance drifts one whole beat behind the
music every ~17 s. Find the offset with `fitBeatOffset(onsets, bpm)` (circular mean
of onset phases) from onsets that `detectOnsets(energy, hop)` picks out of an
`AnalyserNode`'s 40–500 Hz energy (spectral flux > 1.6 × its recent mean, ≥ 120 ms
apart). The lab locks after 8 s of music. Add `AudioContext.outputLatency` when
the clock reads `audio.currentTime` on a device with long output latency (Bluetooth).

### 6.2 Curves (why it looks like dancing)

| Curve | Formula | Use |
|---|---|---|
| **pop** | rises in the last `attack` s before the beat as `(1 − until/attack)²` (accelerating), **1 on the beat**, holds `hold` s, falls with `1 − smoothstep((since − hold)/release)` | hits: chest pops, arm hits, claps. Defaults attack 70 ms, hold 60 ms, release 350 ms; chest pop release 220 ms so the next hit reads; claps 80/40/250 ms. Times in seconds, so a hit is equally sharp at 90 and 160 BPM |
| **bounce** | `−(0.5 + 0.5·cos 2π·phase)^sharp` | the groove: lowest **on** the beat (knees give), back up by the off-beat. sharp 2 (smooth) – 3 (punchy) |
| **step** | ±1 alternating on each beat, moving only in the last 45 % of the beat (smoothstep) | weight shifts, two-step, disco point: arrive on the beat, dwell |
| **wave** | `sin(2π(beat/beats − lag))` | rolls and ripples: each joint lags the one before |

Crossfades between moves: smoothstep over 0.5 beat, **centred on the count**, so
the change itself lands on the beat; finishers use 0.2 beat (a snap).

### 6.3 The move library (`MOVES` in `dance.js`)

All angles are added to rest, in the plush convention (§5). `b` = bounce, `k` = pop.

| Move | Counts | Recipe |
|---|---|---|
| `bounce` | 8 | hipsY 0.03·b, stretch 0.05·b, head x −0.12·b, legs x 0.08·b, arms loose |
| `chestPop` | 4 | per beat: chest x −0.34·k (arch out), hips x +0.1·k, head x +0.16·k − 0.05 (counter), arms back 0.4·k, stretch 0.09·k + 0.03·b, lift 0.015·k; `double`: a 60 % pop on the "and" (release 120 ms) |
| `twoStep` | 8 | s = step(beat): sway 0.12·s, hips y 0.25·s, chest y −0.2·s, the leg on the step side out 0.25, arms swing across 0.6 ± 0.5·s, bounce under it |
| `armWave` | 8 | a ripple over 4 beats: armL raise 1.1 + 0.35·w(0), chest z 0.14·w(0.12), head z −0.12·w(0.18), armR 1.1 + 0.35·w(0.25) |
| `point` | 4 | disco point: s = step(beat, 0.35); up = (s+1)/2; armR raise 0.45 + 1.15·up, forward 0.1 + 0.9·(1−up) (diagonal up ↔ across the body), reach 0.2·up; other paw to the hip; sway −0.1·s |
| `bodyRoll` | 4 | over 2 beats, pitch: head 0.22·w(0), chest 0.26·w(0.12), hips −0.2·w(0.25), knees 0.12·w(0.3) |
| `clap` | 4 | paws together on **2 and 4** (pop on odd beats, closing in during the second half of even beats); bounce on every beat; head bob z 0.12·sin(π·beat) |
| `roof` | 4 | raise the roof: both arms 1.15 + 0.45·k (a V), reach 0.12·k, head up −0.25 − 0.1·k |
| `spin` | 2 | yaw 2π·smoothstep(u) (wrapped, so the fade out doesn't unwind), hop 0.08·sin πu, arms out 0.9 |
| `hit` | 4 | the button: armR up the diagonal 1.6 with reach 0.2, armL to the hip, head tilt, sway −0.1; a settle pop on its first beat |
| emotes `hello`, `cheer`, `shrug`, `bow` | 2–4 | hello: armR raise 1.6, forward 0–0.7 at 2 Hz, reach 0.25; cheer: jumps every 2 beats (crouch 20 %, air 60 %, land 20 % with squash), arms a V 1.3→1.65; shrug: pop over 2 beats (attack 180 ms, hold 350 ms); bow: 30 % down, 35 % hold, 30 % up |

`mirrorPose` swaps sides (arms/legs swap, y/z turns and sway/yaw flip);
`clampPlushPose` keeps everything inside `PLUSH_LIMITS`.

**Slow and smooth (real dancing to a fast song).** The moves above hit on every beat:
at 143.6 BPM they peak at 20–28 rad/s with a jerk of 30 000–130 000 rad/s³ and read
as jittery. Dancers to a fast track move in **half time**: arrive on every other
beat, hold, flow on. The slow set (`bounceSway`, `reachUp`, `sideClap`, `lazySway`,
`bodyWave`, `sultrySway`, `pawArc`, `slowPop`, `armFlow`, `heavyStep`,
`rollShoulders`, `squatRise`, `wideWiggle`, `waddleGlide`, `flipperWave`,
`slowTurn`, `strike`) is built from four curves: `glide(beat, per, hold)` (a weight
shift that lands every `per` beats, dwells, then crosses with a sine ease),
`groove(beat, per)` (a soft knee bend, a pure sine, lowest as the weight lands),
`swell(beat, per, at, { rise, hold, fall })` (a slow hit: eased in to land on the
count, held, eased out) and `easeSine`; and on **follow-through**: `LAG` — the hips
lead, the chest 90 ms behind, the arms 160 ms, the head 200 ms (`lagged(c, s)`).
Crossfades 1.5 beats. Result: under ~3.7 rad/s, jerk under ~2 000, no hops. The podium
signatures (`signatures.js`) then went **1.5× quicker** at the user's ask: the same half-time
moves played at `RATE` 1.5 (three dance counts to two beats of the song, from a bar line, so
still locked to it; holds ⅔ as long, every move done in ⅔ the time; the lags stay in ms):
under ~5.7 rad/s, jerk under ~4 200 (tested in `motion-signatures.test.mjs`, ≤ 6 rad/s).
Springs for ears and tails go softer with it (k 20–30, d 3–3.6: they flow).

**Seven styles, not one dance seven times.** Built from the same slow sway, the seven
signatures read as one dance on screen (the user: "those characters dance the same thing"):
joint angles only 0.15–0.36 rad apart on average, one bar 0.10. Each character now has its own
**style** (dance.js, after the slow set): its own signature move, its own **rhythm** and its
own **silhouette** — the bunny's `bunnyHop` (a 6 cm hop off every beat, a foot kicking forward
in turn, paws up by the cheeks: narrow, vertical), the pig's `pendulum` (wide legs, the whole
body swinging out to a side on every beat with a swing feel — knee dips on the beat and on the
swung "a" — belly circles, claps on 2 and 4, a V clapping overhead), the cat's `catWave` /
`catClaw` / `catSpin` (body waves, hip pops landing on the "and" — `held` on a half-beat grid —
a claw swipe framing the face, a spin on one foot), the fox's `robot` / `foxPop` (tutting: a held
pose on every beat from straight lines and right angles, one arm moving at a time, over half a
beat; chest pops, head snaps, quarter-turn clicks), the bear's `bearStomp` / `bearRock` (knee up
and stomp on 1 and 2, the body dropping into it, a double-biceps flex over 3–4 then a crab; a
heavy rock), the frog's `frogSwim` (a deep knees-out squat, breaststroke paws, a 13 cm leap every
two bars), the penguin's `penguinWaddle` / `penguinGlide` (a stiff rock on every beat, flippers
swept back and flapping on the off-beat, skating glides, a whole spin every two bars). They are
written in the **song's beats** (`sb(c)` = counts ÷ `RATE`) and the cycle is 48 counts (8 bars),
so a hit on the beat stays on the beat across steps and cycles. Every pair is now 0.31–0.54 rad
apart (mean 0.40), every bar over 0.18 (`motion-signatures.test.mjs`). What made them read
apart: the arms' resting height and direction (by the cheeks, low and wide, one up by the face,
straight out, flippers back), the stance (narrow, wide, deep squat), the body's path (up and
down, side to side, turning) and the timing (every beat, swing, syncopated, staccato). Keeping
them smooth: sine-squared bumps (they start and stop still: a plain sine bump's kink is a jerk
spike), whole turns with a trapezoid speed (`turnAt`: peak 4/3 of the mean, a sine ease's is
π/2), and the winner's V rising over 2 counts — a V raised from paws far from it (the bear's crab)
otherwise goes past 6 rad/s; when the winner hops, the dance's own legs let go as the paws rise.

### 6.4 Routines and original combos

`routine(steps)` plays `{ move, counts, mirror, amp, double }` steps in a loop with
crossfades; `sample(clockState)` → pose. `makeCombo(seed, { bars })` composes an
**original** combo: 8-count phrases of two 4-count halves; opens on the groove
(`bounce`); no move twice in a row; a one-sided move (`point`, `armWave`) is
answered by its mirror; the last phrase ends on `spin` + `hit`. Same seed, same
combo (for online play, send the seed and the start beat: every client dances the
same thing with zero animation traffic).

### 6.5 On a plush rig

```js
import { beatClock, routine, makeCombo, applyPlushPose, secondary } from '../shared/motion/dance.js';
const clock = beatClock(143.6, { offset });
const show = routine(makeCombo(seed, { bars: 8 }));
// each frame (instead of PlushRider.celebrate):
const pose = show.sample(clock(musicTime));
applyPlushPose({ bones: r.bones, squash: r.squash, tilt: r.tilt, turn: r.body, turnRest: Math.PI }, pose);
const s = secondary(springState, pose, dt);   // ears and tail
r.bones.get('earL').rotation.set(s.ear[0], 0, -0.08 - s.ear[1]); // …earR mirrored, tail
```

## 7. Secondary motion, IK and motion matching

**Springs** (`spring(s, goal, k, d, dt)`, semi-implicit Euler): critically damped
when `d = 2√k`; less damping = floppier. Ears k 70, d 6 (≈ 1.3 Hz wobble, settles in
~0.8 s); sway follow k 45, d 5; tails k 55, d 4. Drive them with the body's
**vertical speed** (a body going up leaves the ears behind; landing flings them up)
and its sway — never with time. Plush squash: scale y `1 + stretch`, x and z
`1/√(1 + stretch)` (volume kept); a landing spring (k 260, d 12) after any hop.

**IK** for feet and hands on humanoids:
- **Two-bone analytic** (thigh–calf, upper arm–forearm): with lengths a, b and
  target distance c (clamped to `[|a−b|, a+b] × 0.999`), the knee angle is
  `acos((a² + b² − c²)/2ab)`, the hip turns to the target by `acos((a² + c² − b²)/2ac)`
  in the plane given by a pole vector (the knee's forward). Exact and cheap: use it
  for foot planting.
- **CCDIKSolver** (`three/addons/animation/CCDIKSolver.js`) for chains of more
  than two bones (tails, tentacles, a spine reaching); needs a SkinnedMesh and an
  `iks` config (target bone, effector, links with rotation limits).
- **Foot planting**: mark contact frames (foot height < 2 cm and speed < 0.3 m/s),
  remember the world position at contact start, and IK the leg to it until
  release; blend the IK weight in/out over 0.1 s. On plush legs (one bone, 0.12
  long) don't IK: drop the hips instead.

**Motion matching** (for a later locomotion-heavy game, e.g. the top-down action
game): a database of poses from long unstructured clips; features per frame =
both feet's positions and velocities, hip velocity, and the future trajectory
(position and facing at 0.33, 0.67, 1.0 s); every ~0.1 s, search the frame whose
features (normalised, weighted) best match the current pose + the player's desired
trajectory; jump there with **inertialization** (decay the pose offset with a
critically damped spring over ~0.2 s) instead of a crossfade. Data: 100STYLE
(CC BY 4.0). For our current games a state machine with crossfades and
speed-matched playback (§4.4) is enough.

## 8. Learning from famous dances without copying them

A famous routine (say, a K-pop chorus with a chest pop) is a **choreographic
work**: protected in Korea (the Copyright Act counts dance among dramatic works)
and in the US as a choreographic work. What isn't protected is the vocabulary:
social dance steps and simple moves (US Copyright Office Compendium §805.5) —
bounce, two-step, chest pop, wave, point, body roll, clap on 2 and 4, shoulder
shimmy, the running man. (General guidance, not legal advice.)

How we learn from one:

1. **Watch for qualities, not steps.** Note the tempo, where the hits fall (on the
   beat, on the "and"), how long holds are, how often the direction changes (every
   8 counts), levels (high/low), and the "hook" — the one recognisable move.
2. **Name the vocabulary.** Write each 8-count as generic moves: "bounce ×4, chest
   pop ×4 on 5-6-7-8, point up-down, body roll".
3. **Compose our own.** New order, our own phrase lengths, call-and-response
   mirrors, our own hook (a plush-specific one: an ear flick, a tail wag on the
   button, a squash hop). `makeCombo` does exactly this from a seed.
4. **Never** reproduce a song's signature sequence move for move, never use its
   music, never name the song or group in a game. Our music is our own
   (`docs/music.md`).
5. **Translate for plush**: humans hit with hands above the head; plush hit with
   the whole body (squash/stretch), the head and the ears, paws in the V envelope.
